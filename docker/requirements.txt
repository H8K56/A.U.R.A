# A.U.R.A. — direct Python dependencies, pinned to the known-good container.
#
# Versions are what the working aura-dev container actually runs, captured
# 2026-09-14 — not aspirational pins. The previous Dockerfile asked for
# numpy==1.24.3 and got 1.26.4, because a later unpinned install overrode it;
# pinning the whole set together is what stops that.
#
# torch is NOT listed here: it needs --index-url for the CUDA variant, so the
# Dockerfile installs it separately from TORCH_* in versions.env.
#
# Full environment record: requirements.lock.txt
# Non-pip components (PX4, px4_msgs, ns-3, ...): versions.env

# Build backend. CI broke building the ament Python eggs with
# "canonicalize_version() got an unexpected keyword argument
# 'strip_trailing_zero'": setuptools passes that keyword, and Jammy's
# apt-provided packaging (21.3) predates it. packaging >= 24 is the fix.
#
# setuptools is deliberately NOT pinned. The dev container runs 80.10.2, but
# pinning that broke pip's resolver on the ros:humble CI image, whose
# colcon-core 0.21.1 requires setuptools<80. Each environment's own setuptools
# is fine once packaging is new enough — setuptools was never the cause.
packaging==26.0
